# StarLux 桃園↔曼谷 票價追蹤

追蹤目標：星宇航空 (JX) 桃園 (TPE) ↔ 曼谷 (BKK)，12/4 出發、12/8 回程，來回經濟艙，單人。

## 這支工具實際在追什麼

星宇官網的訂票引擎是動態頁面（需要 JS 執行、實際選位才有精確報價），Google Flights 也一樣，
兩者都無法用簡單的排程腳本穩定爬到「12/4 出發、12/8 回程」這組日期的精確總價，而且都會主動
擋自動化流量。

但星宇官網的航線頁（`flights-from-taipei-to-bangkok`）本身是伺服器端渲染的，會內嵌兩份資料，
不需要瀏覽器就能讀到：

1. **未來約 6 個月的「當月最低價」卡片輪播**：例如「December 2026, From TWD9,622, Seen: 1 day ago」。
   這是本工具每天實際追蹤的訊號 —— 12月來回經濟艙目前公開的最低快取價，不等於 12/4-8 這組日期的價格，
   但能反映這條航線 12 月的價格走勢。
2. **一組「最近被查詢過」的範例報價**（任意艙等、任意日期組合）。腳本會順便掃這幾筆，如果剛好有一筆
   出發/回程日期對到 12/4-8（或很接近），會額外標註出來 —— 但這是可遇不可求，不保證每天都有。

## 檔案

- `track_fare.py`：抓官網頁面、解析上述兩份資料、寫一行進 `data/price_history.csv`
- `notify_telegram.py`：讀最新兩筆記錄、組成中文訊息、透過 Telegram Bot API 送出
- `data/price_history.csv`：每天一筆歷史記錄（由 GitHub Actions 自動累積、自動 commit）

## 排程

`.github/workflows/starlux_fare_tracker.yml`：每天 UTC 01:00（台北時間 09:00）自動執行一次，
也可以在 GitHub Actions 頁面手動 "Run workflow" 立即跑一次。

## 需要設定的 Secrets

Repo 的 `polymarket_bot` 專案已經設定過 `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` 這兩個 Secrets，
本工具直接沿用同一組（同一個 Bot、同一個聊天室會收到兩種通知）。如果想改成傳到別的聊天室，
到 repo 的 Settings → Secrets and variables → Actions 更新這兩個值即可，不需要改程式碼。

## 已知限制

- **抓不到「過去一個月」的逐日歷史價格**：這是新追蹤的資料，過去沒有人每天記錄，Wayback Machine
  的存檔也證實了 12 月這組資料是最近才進入官網的「未來 6 個月」顯示範圍內，更早的存檔（2/3、3/12、
  6/11）都還看不到 12 月的價格卡片。等這支腳本跑滿一個月，就會有真正屬於這條路線的歷史趨勢資料。
- **每日追的是「當月最低價」，不是「12/4-8 精確總價」**：如上述說明，這是目前用純 HTTP 請求能穩定
  拿到的最接近訊號。如果之後想要精確到那組日期的報價，需要改用會執行 JS、模擬真人操作訂票流程的
  瀏覽器自動化（例如 Playwright），維護成本高很多，也更容易被官網的反機器人機制擋下來。
